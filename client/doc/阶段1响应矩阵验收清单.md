# 阶段 1 响应矩阵验收清单

## 阶段目标

把招标文件解析结果整理成可追踪的响应矩阵。

阶段 1 的重点是“要求清单稳定、可查看、可编辑、可持久化”。不要求完成大纲覆盖自动回写，也不要求正文生成使用矩阵。

## 前置条件

进入阶段 1 验收前，应满足：

- 阶段 0 已通过用户验收。
- 已上传完整招标文件。
- 招标文件解析已完成。
- 至少完成以下解析项：
  - 技术评分要求
  - 交货和服务要求
  - 响应文件要求
  - 符合性检查
  - 无效标与废标项

推荐使用阶段 0 的真实招标文件作为第一轮验收样本：

- `(招标文件)华能清能院BIM模型融合编辑系统采.doc`

## 功能验收项

### 1. 生成矩阵

操作：

1. 进入 `生成技术方案`。
2. 打开 `招标文件解析` 页面。
3. 在响应矩阵视图点击生成或刷新矩阵。

通过标准：

- 能生成一张响应矩阵。
- 矩阵至少包含技术评分项、响应文件要求、符合性要求、废标风险项。
- 生成失败时有明确错误提示，不留下半完成的空白状态。

### 2. 分类正确性

通过标准：

- 技术评分项归类为 `scoring` 或 `technical`。
- 响应文件组成、格式、签章、逐条响应要求归类为 `mandatory`。
- 符合性检查项归类为 `mandatory`。
- 无效标、废标、否决投标、实质性偏离归类为 `rejection`。
- 交付、验收、质保、售后、培训、文档要求分别归入 `delivery`、`acceptance`、`service` 或 `mandatory`。

### 3. 风险等级

通过标准：

- 废标风险项默认为 `high`。
- 强制响应项默认为 `high`。
- 技术评分项默认为 `high` 或 `medium`，不能全部低风险。
- 普通背景信息不能被大量标为 `high`。

### 4. 来源信息

通过标准：

- 每条要求保留原始要求文本或摘要。
- 每条要求有来源线索，例如章节、条款、表格名或原解析项。
- 不承诺页码精确，但不能完全没有来源。

### 5. 人工编辑

操作：

1. 选择一条要求。
2. 修改状态为 `需确认` 或 `忽略`。
3. 填写用户备注。

通过标准：

- 状态能保存。
- 用户备注能保存。
- 切换页面后不丢失。
- 刷新应用状态后不丢失。

### 6. 矩阵刷新

操作：

1. 已有矩阵后再次刷新矩阵。
2. 检查已编辑过的条目。

通过标准：

- 已有用户备注不被静默覆盖。
- 已人工设置的状态不被静默改回默认值。
- 新识别出的要求可以追加。

### 7. 清空技术方案

操作：

1. 使用技术方案清空功能。
2. 重新进入招标文件解析页面。

通过标准：

- 响应矩阵被清空。
- 旧矩阵不会残留到新项目。

### 8. 数据库持久化

通过标准：

- SQLite 中存在 `technical_plan_requirements` 表。
- 关闭并重启客户端后，矩阵仍能加载。
- 数据库健康检查能修复缺失的响应矩阵表。

## UI 验收项

响应矩阵视图至少应包含：

- 统计信息：总要求数、高风险数、未覆盖数、需确认数。
- 列表字段：类型、重要程度、标题、来源、状态、关联章节数量。
- 详情字段：原文要求、风险原因、证据备注、用户备注。
- 过滤能力：全部、高风险、未覆盖、需确认、已忽略。
- 操作能力：生成矩阵、刷新矩阵、编辑状态、编辑备注。

## 不属于阶段 1 的范围

以下内容不在阶段 1 验收范围：

- 自动判断每条要求是否已被大纲覆盖。
- 目录节点多要求绑定。
- 正文生成时按章节注入矩阵要求。
- 防废标审查报告。
- 局部修改正文。
- Word 模板套用。

这些分别属于阶段 2、阶段 4、阶段 5、阶段 6、阶段 7。

## 阶段 1 通过标准

阶段 1 可以验收通过的最低标准：

1. 真实招标文件解析后能生成响应矩阵。
2. 矩阵能区分评分项、强制项、符合性项和废标风险项。
3. 用户能编辑状态和备注。
4. 矩阵能持久化。
5. 清空技术方案能清空矩阵。
6. `npm run build` 通过。
