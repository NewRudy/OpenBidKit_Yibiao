# 技术标工作台分阶段改造方案

## 目标

把现有“生成技术方案”能力改造成可验收的技术标生产工作台。核心不是让 AI 自由写作，而是围绕招标文件要求形成可追踪的生产链路：

```text
招标文件解析 -> 响应矩阵 -> 大纲覆盖 -> 逐章节生成 -> 审查防废标 -> 局部修改 -> Word 导出
```

前台保持确定流程，后台可以拆分为多个专职任务。不要在第一阶段做可见的 agent 矩阵；标书场景优先保证覆盖、证据、可复核和可暂停恢复。

## 权威依据与设计约束

截至 2026-06-30，最新的国家层面方向与我们的改造路线一致。国家发展改革委等 8 部门 2026 年发布的《关于加快招标投标领域人工智能推广应用的实施意见》明确把 AI 用于“投标策划”和“投标合规自查”，其中包括自动提取招标资料关键要素、生成招标需求图谱、对投标文件和招标文件做响应性比对、提示错误缺漏并辅助修改完善。

这说明第一版不应先做自由写作型 agent，而应先做以下确定性工作流：

- 提取招标要求，形成可复核的需求图谱，也就是本方案里的响应矩阵。
- 将大纲、正文和审查都绑定到同一组招标要求。
- 生成后做响应性比对、错误缺漏提示和修改建议。
- 保持 AI 的辅助定位，模型结论不替代用户最终判断。
- 对模型幻觉、数据安全和错误缺漏风险做显式提示和人工确认。

法律和采购规则上，核心约束是“实质性响应”。《中华人民共和国招标投标法实施条例》第五十一条列明，投标文件没有对招标文件的实质性要求和条件作出响应时，评标委员会应当否决其投标。财政部令第 87 号《政府采购货物和服务招标投标管理办法》也要求评标委员会审查、评价投标文件是否符合招标文件商务、技术等实质性要求，并通过符合性审查确认是否满足实质性要求；其第六十三条还列明多类投标无效情形。

因此，本项目的产品判断顺序是：

1. 先保证强制项、废标项和实质性要求不漏。
2. 再保证技术评分项有针对性覆盖。
3. 再提升文本质量、排版和表达。
4. 最后再考虑更复杂的多 agent 自动协作。

## 阶段 0：基线验收

目标：跑通原仓库技术标主流程，确认现有效果和问题。

验收口径：

- 模型配置可用。
- 本地解析能导入一份真实招标文件。
- 招标文件解析能产出项目概述、技术评分要求和关键项。
- 目录生成能跑通。
- 用户能指出现有大纲是否贴合招标文件，以及明显漏项。

当前状态：

- GLM-4.7 OpenAI-compatible 配置已通过连通性测试。
- Electron、better-sqlite3 和前端构建链路已修通。
- 已用完整招标文件完成扩展解析和目录生成基线试跑，详见 `阶段0真实文件试跑记录.md`。
- 目录生成结果暴露出一级占位项“新目录项”，需要在阶段 2 的大纲覆盖与清理中修复。
- 阶段 0 等待用户验收后进入阶段 1。

## 阶段 1：响应矩阵

目标：把招标文件解析结果升级成可追踪要求清单，作为大纲、正文生成和防废标检查的共同事实源。

### 数据结构

建议新增响应矩阵实体，先落 SQLite，后续再按需要拆分更多表。

```ts
interface TenderRequirement {
  id: string;
  requirementType:
    | 'scoring'
    | 'mandatory'
    | 'technical'
    | 'delivery'
    | 'acceptance'
    | 'service'
    | 'qualification'
    | 'rejection'
    | 'business'
    | 'other';
  title: string;
  originalText: string;
  sourceLocation: string;
  importance: 'high' | 'medium' | 'low';
  responseStatus: 'unmapped' | 'mapped' | 'needs-confirmation' | 'ignored';
  outlineNodeIds: string[];
  evidenceNotes: string;
  riskReason: string;
  userNotes: string;
  sortOrder: number;
  createdAt: string;
  updatedAt: string;
}
```

第一版字段要保守，不承诺页码精确定位；`sourceLocation` 可以先保存章节、条款、表格位置或模型提取出的线索。

### 提取策略

从现有 `bidAnalysisTask.cjs` 中已有的解析项开始，不新开一套完全独立流程：

- 技术评分要求 -> `scoring`
- 项目信息、甲方信息、交付和服务要求 -> 全局事实候选
- 采购清单、响应文件要求、资格性审查、符合性检查 -> `mandatory` / `technical` / `qualification`
- 无效标与废标项 -> `rejection`
- 商务评分要求、保证金、合同授予签订 -> 后续商务标使用

第一版可由 AI 将上述解析结果归并为矩阵 JSON，再由程序校验、补 ID、落库。后续再增加基于招标全文的二次补漏。

### 页面形态

在技术方案 Step02 后增加“响应矩阵”视图，或把 Step02 改成“解析结果 / 响应矩阵”双视图。

列表主列：

- 类型
- 重要程度
- 要求标题
- 原文摘要
- 来源位置
- 覆盖状态
- 关联章节数量

详情区：

- 原文要求
- 风险原因
- 关联大纲节点
- 用户备注
- 人工状态调整

### 交互原则

- 用户能手动把某条要求标记为“忽略”或“需人工确认”。
- AI 不能静默删除高风险要求。
- 生成大纲前，如果存在 `high` 且 `unmapped` 的强制项，应提示用户。
- 目录生成后必须回写 `outlineNodeIds`，为阶段 2 提供覆盖证据。

### 验收口径

- 上传招标文件并解析后，能看到一张要求矩阵。
- 技术评分项、强制响应项、废标风险项能被区分。
- 至少能手动编辑状态和备注。
- 矩阵数据刷新页面后仍保留。

## 阶段 2：大纲与覆盖关系

目标：大纲不只是标题树，而是每个章节都说明覆盖哪些招标要求。

关键改造：

- 目录节点展示覆盖数量和风险标记。
- 支持从未覆盖要求反查建议章节。
- 目录保存时同步更新响应矩阵覆盖关系。
- 生成正文时只给章节传入相关要求，降低跑偏概率。

验收口径：

- 用户能看到每个目录节点对应的评分项/强制项。
- 用户能看到未覆盖要求清单。
- 单个章节生成前能查看其输入上下文。

## 阶段 3：经验 Skill 库

目标：把用户的写作经验沉淀为可复用规则。

建议命名为“经验卡”，避免和 Codex runtime skill 混淆。

```ts
interface WritingExperienceCard {
  id: string;
  title: string;
  applicableSections: string[];
  tags: string[];
  requirements: string;
  forbidden: string;
  exampleText: string;
  priority: number;
}
```

生成章节时，系统根据章节标题、要求类型和标签匹配经验卡；用户也可以手动指定。

验收口径：

- 用户能新增经验卡。
- 某个章节能手动绑定经验卡。
- 生成内容能体现经验卡要求。

## 阶段 4：逐章节生成队列

目标：按叶子章节独立生成，支持暂停、重试、单章重写和上下文查看。

关键改造：

- 章节任务状态更细化。
- 单章生成前展示：招标要求、全局事实、经验卡、同级目录。
- 单章失败不影响其他章节。
- 支持只重写某一小节。

验收口径：

- 用户可以单独生成某一小节。
- 用户可以查看该小节引用了哪些要求和经验卡。
- 单章重试能保留其他章节内容。

## 阶段 5：审查与防废标

目标：生成初版后做响应覆盖、一致性和废标风险检查。

检查范围：

- 强制项漏响应。
- 技术评分项覆盖不足。
- 项目名称、工期、人员、金额、服务期不一致。
- 废标项和无效标风险。
- 明显逻辑矛盾。
- 过度承诺或招标文件未要求的敏感承诺。

验收口径：

- 检查结果按问题项展示。
- 每项包含依据、正文证据、风险原因和修改建议。
- 用户能删除、忽略或标记已处理。

## 阶段 6：局部修改

目标：对一句话或一段文字做 AI 修改，不重写全文。

交互：

```text
选中段落 -> 输入修改要求 -> AI 返回修改建议 -> 用户确认替换
```

技术原则：

- 默认必须唯一命中原文。
- 替换前展示 diff。
- 替换后记录修改日志。
- 如果修改涉及全局事实，提示用户复核。

验收口径：

- 用户能安全替换单段文本。
- 修改前后可查看。
- 不会误改多个相似段落。

## 阶段 7：Word 模板

目标：让导出文档贴近用户自己的 Word 技术标模板。

第一版支持：

- 标题 1/2/3 样式。
- 正文样式。
- 表格样式。
- 页眉页脚。
- 编号规则。
- 目录样式。

复杂企业模板先不承诺完全还原；先保证常规技术标模板可用。

验收口径：

- 用户能上传 `.docx` 模板。
- 导出文档能复用主要标题、正文、表格样式。
- 目录编号和层级基本正确。
